# Лабораторная работа 1. Python-клиент для SampleAPIs Coffee

Лабораторная работа: исследование публичного API горячего кофе и клиент на Python с `requests`.

## Задача

Клиент в `starter.py` умеет получать список напитков, читать запись по `id`, создавать её, заменять через PUT, изменять через PATCH и удалять.

## API

Базовый URL: `https://api.sampleapis.com/coffee/hot`

| Операция               | Метод и путь      | Статус | Ответ            |
| ------------------------------ | --------------------------- | ------------ | --------------------- |
| Список напитков  | `GET /coffee/hot`         | `200`      | JSON-массив     |
| Один напиток        | `GET /coffee/hot/{id}`    | `200`      | JSON-объект     |
| Нет такой записи | `GET /coffee/hot/{id}`    | `404`      | `{}`                |
| Создать                 | `POST /coffee/hot`        | `201`      | объект с`id` |
| Заменить               | `PUT /coffee/hot/{id}`    | `200`      | JSON-объект     |
| Изменить               | `PATCH /coffee/hot/{id}`  | `200`      | JSON-объект     |
| Удалить                 | `DELETE /coffee/hot/{id}` | `200`      | `{}`                |

### Данные напитка

```json
{
  "title": "Lab1 Coffee team-tag",
  "description": "Coffee for the lab",
  "ingredients": ["espresso", "water"],
  "image": "",
  "id": 123457
}
```

Для POST клиент передаёт `title` (строка), `description` (строка), `ingredients` (массив строк) и `image` (строка). POST только с `title` вернул `400` и показал ожидаемые поля и типы. Пропуск каждого поля по отдельности не проверялся, поэтому список необязательных полей не установлен. Пустая строка `image` была принята. Поле `id` добавляет сервер.

В POST используется `Content-Type: application/json` (его выставляет `requests` при `json=`) и `Accept: application/json`. Сервер вернул `201` и объект с переданными полями и `id`.

## Сценарий

1. Получить список напитков.
2. Создать запись с уникальной меткой группы.
3. Получить её по `id` из ответа POST.
4. Заменить данные через PUT.
5. Изменить одно поле через PATCH.
6. Повторно получить запись и сравнить поля.
7. Удалить запись.
8. Проверить, что GET вернул ожидаемый `404`.

Программа меняет и удаляет только запись, созданную ею. Повторы запросов не выполняются. Если POST завершается тайм-аутом, результат неизвестен: программа выводит метку для ручной проверки. При ошибке после получения `id` она пытается удалить запись.

## Реализовано

- запросы выполняются через `requests`, без `Session`;
- тайм-аут задан для каждого запроса;
- статус и `Content-Type` проверяются до разбора тела;
- `404` обрабатывается отдельно от остальных ошибок API;
- после POST используется `id` из ответа;
- после PUT и PATCH сохранённые данные сверяются через GET;
- при ошибке до DELETE программа пытается удалить созданную запись.

## Запуск

Нужен Python 3.10 или новее.

```bash
python3 -m pip install -r requirements.txt
python3 starter.py
```
